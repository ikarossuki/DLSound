# DL Sound 1.4.3 代码审查与回归

本次以 1.4.2（36）为基线，覆盖仓库中的手机应用、数据层、领域层、共享模块、Wear 和同步代码，以及构建、签名和验收脚本。对播放与后台生命周期、字幕来源、队列、存储、旧数据迁移、备份和正式包发布路径进行了调用链审查。构建、静态分析和设备验证范围分别记录如下。

## 修复与验证

| 使用场景 | 问题及修复 | 验证 |
| --- | --- | --- |
| 旧版升级 | 先读书签会推断出空的 RJ 作品，使随后读取的正式作品资料被跳过。现在先迁移显式作品，再迁移书签。以前已迁移的设备只补全符合旧占位特征的现存作品，数据写入成功后才记录完成。 | 用真实 SQLite 写入“书签在前、作品在后”的旧网页数据。分别验证首次升级、已迁移设备的修补、再次运行、保留编辑、保留删除。 |
| 同一文件的书签 | 树目录、单文件授权、文件路径及曲库可能以不同地址指向同一音频。新建、读取和导出书签时统一 Android 外部存储文件的地址。其他提供方保留自己的 URI。 | 带百分号、空格和日文的文件名，主存储路径、两种系统 URI 和第三方 URI。正式包覆盖升级后原书签仍在。 |
| 文件夹续听 | 文件大小未知、同一地址下文件被替换、换机前已备份第二个文件时，曾可能误清或串用续听。现在先绑定文件身份，再校验有效大小和修改时间。 | 用同一地址反复切换三个大小，检查真正换文件时从头播放、原文件和备份记录各自保留、缺元数据时续听不丢。另用正式包走系统目录选择器锁屏播放并重新打开。 |
| 暂停和切歌 | 延迟返回的解码器进度可能写到下一首。暂停、定期保存和主动跳曲按队列项 ID 写入，暂停回调返回时确认仍是同一项。 | 域层测试分别延迟和立即返回暂停进度。正式包验证后台暂停、外部打开以及终止进程后的续听。 |
| 队列和撤销 | 删除或移动后排序号可能不连续。窗口查询按实际排名裁切并取消旧曲目的订阅。撤销删除只消费一次，会为被占用的位置让位，清空或更换队列后释放旧撤销记录。 | Android Room 内存库同时验证正常及随机顺序、稀疏排序号、移动、位置冲突、重复撤销和清空后的撤销。另在正式包的 1,100 首曲库中拖放并点播。 |
| 字幕与备份 | 手动选字幕曾按音频方式额外打开文件。现在单独查询名称及父目录，直接读取字幕内容。修正旧学习控件定位字幕时对偏移的处理。备份在打开系统选择器及结果返回时，都校验曲库权限和加载结果。 | 检查 1,600 句带假名字幕仅打开一次、两条音轨绑定相同文本时隔离读音修正、无效备份不会写入歌单。目录授权和原有歌单在正式包覆盖升级后可用。 |
| 构建和平台兼容 | 去除对 AndroidX 内部菜单类型的依赖，使用原生断行常量和带可见性声明的动态广播注册。删除过时的字幕提示，并补齐仍使用的字幕、目录和读音提示资源。Windows 同一检出的构建现按顺序使用输出目录。 | 五个手机构建模块的 release lint 为零 Error。实测第二个构建等待第一个释放目录后才进入 Gradle。公开更新地址使用当前仓库名。 |

## 测试结果

- 手机和核心模块离线构建。JVM 单元测试 235 项通过，含应用 64、领域 70、数据 101。验收工具的 4 项 Python 测试通过。
- 对仓库跟踪的 8 个 PowerShell 脚本、8 个 Python 脚本和 20 个 JavaScript 文件完成语法检查。设备验收工具可直接向已聚焦的输入框写入指定搜索词，避免系统输入法改写用例中的曲名。
- Android API 37 模拟器运行了两个设备回归阶段，共返回 11 组通过结果。其中四组专门覆盖本次的旧数据、书签、续听及稀疏队列。测试使用独立的临时数据库和偏好文件。旧设备回归也改从系统媒体库打开合成音频。
- 在同一模拟器用正式签名 APK 覆盖 1.4.2。已安装 APK 的 SHA-256 与交付文件一致。之前公开的 1.3.7 与本版签名证书一致。已检查大曲库滚动返回、搜索框焦点、原歌单顺序、书签和目录授权。正式播放页在三个时间点分别显示一、二、一条当前日中字幕，拖动歌词后可恢复跟随。
- 锁屏测试中，单句复听保持在 14 至 16 秒区间，连续复听前进到第二句，本首结束定时器正确暂停。手选目录锁屏暂停后再打开，进度从 48,655 毫秒恢复到 49,018 毫秒。检查点取样时应用没有持有部分唤醒锁或运行前台播放服务。以上为模拟器功能结果，真机耗电百分比仍无实测。
- 播放和暂停两种状态各退到桌面 70 秒，再从最近任务返回同一个播放页。播放中的时间从 5 秒推进到 78 秒，暂停时保持在 79 秒，两次均返回原任务和进程。
- 手机应用、手机打包模块、数据层和两个共享模块的 release lint 报告合计仍有 255 条 Warning 和 3 条 Hint，包含 Kotlin 扩展建议、既有多语言复数文本和旧 API 分支。已查看报告，保留原有 lint 规则。
- Wear 的列表差异测试使用工程内实际编译的实现和本机 JUnit 独立运行，31 项全部通过。完整 Wear Lite 独立 APK 的离线构建缺少锁定版本的 Google Play Services Wearable 及 AndroidX Wear 等依赖，本次没有生成手表安装包，也没有在手表上实测。
