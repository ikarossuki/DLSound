# DL Sound 字幕格式

## 把字幕放在哪里

将音频与同名的 UTF-8 字幕放在同一目录。例如，`第01话.mp3` 或 `第01话.wav` 都可以搭配 `第01话.vtt`、`第01话.lrc` 或 `第01话.srt`。在播放器的「文件访问」中授权该目录，播放时会自动匹配文件名，扩展名大小写均可。

同目录有多份同名字幕时，自动匹配依次选用 `.hms.json`、`.vtt`、`.lrc`、`.srt`。这保留了已有 Himitsu 字幕的优先级。想用另一份时，在「字幕与读音 → 导入字幕」选择文件。手动选择只绑定这一首音轨，点「字幕来源」可以恢复自动匹配。

## VTT 日中双语与上方假名

已有普通 VTT 可直接使用。制作双语字幕时，在同一条字幕中用 `<lang ja>` 标明日文、`<lang zh>` 标明中文。也支持 `ja-JP`、`zh-Hans` 等语言标签。可选的 `<ruby>` 包住原文和读音，`<rt>` 里写假名。例如以下内容可保存为 `第01话.vtt`。

```vtt
WEBVTT

00:00:01.250 --> 00:00:03.400
<lang ja><ruby>明日<rt>あした</rt></ruby>、また。</lang>
<lang zh>明天见。</lang>
```

选择「双」可同时看台词和译文，选择「日」或「中」可单独看一种语言。假名开关控制读音的显示。整条字幕未标语言时，各语言模式都显示原文并保留换行；仅凭两行的先后顺序无法确定翻译关系。播放器使用字幕的起止时间，忽略定位、样式和注释块。

## SRT

同名 SRT 直接按起止时间显示，支持编号、多行正文和字幕之间的停顿。切换「日／中／双」时，未标语言的 SRT 始终显示原文。若要分别切换日文和中文，推荐使用带语言标签的 VTT 或下面的双语 LRC。

```srt
1
00:00:01,250 --> 00:00:03,400
明天见。
```

## 已有 LRC 的约定

双语 LRC 用全角竖线 `｜` 分隔日文和中文。可在日文部分用 `{原文|平假名}` 指定词的读音，例如下面这条合成测试句。

```text
[00:01.250]{人間|にんげん}は言葉を使います。　｜　人类使用语言。
```

文件使用 UTF-8，可带 BOM。支持一行多个时间戳、相同时间的多条内容、长分钟数、`offset`、空白定时行和常见元数据。括号开头的场景提示在独立区域保留约 4 秒。更精确的场景结束时间通过 `.hms.json` 的 `endMs` 提供。

没有分隔符的普通行按日文展示。含假名的日文会进入自动分析，未标注且只有汉字的模糊行保留原文。要指定读音，可以直接写成 `{原文|平假名}`。

## 高级格式 Himitsu JSON

完整可复制示例见 [学习示例.hms.json](../examples/学习示例.hms.json)。所有内容均为合成测试句，不来自现有音声或待核对剧本。

```json
{
  "format": "himitsu-subtitles",
  "version": 1,
  "documentId": "lesson-001",
  "cues": [
    {
      "id": "line-001",
      "kind": "dialogue",
      "startMs": 1200,
      "endMs": 5500,
      "ja": [
        { "text": "人間", "reading": "にんげん" },
        { "text": "は言葉を使います。" }
      ],
      "zh": "人类使用语言。"
    }
  ]
}
```

### JSON 字段说明

| 字段 | 含义 | 制作要求 |
| --- | --- | --- |
| `format` | 格式标识 | 固定为 `himitsu-subtitles` |
| `version` | 格式版本 | 第一版固定为整数 `1` |
| `documentId` | 这份字幕的稳定标识 | 非空文本，同一份字幕后续修订尽量保留；不是音频路径 |
| `cues` | 字幕条目数组 | 可为空；同时间不同内容分成不同条目，不合并丢弃 |
| `id` | 当前条目的稳定标识 | 同文件内唯一，例如 `line-001`；调整顺序时保留 ID |
| `kind` | 条目种类 | `dialogue` 为台词，`scene` 为场景提示 |
| `startMs` | 开始毫秒 | 大于或等于 0 的整数，例如 1 分 2.5 秒为 `62500` |
| `endMs` | 结束毫秒 | 若提供，必须大于开始时间；场景提示必须提供 |
| `ja` | 日文 | 台词可为普通字符串，或按原文顺序组成的片段数组；提示只用字符串 |
| `zh` | 中文 | 普通字符串，可省略；每条至少有 `ja` 或 `zh` 一项 |
| `text` | 一个原文片段 | 非空，所有片段顺序拼接后就是完整日文，不插入额外空格 |
| `reading` | 此片段的上方假名 | 可省略；提供时用平假名，可包含长音符、间隔符和空格 |

`ja` 不带精确读音时也可以直接写成 `"ja": "日本語を勉強しています。"`，应用按注音设置使用离线读音生成；允许部分片段提供读音、其他片段留给自动处理。

对人名、特殊读法和多音字，可以把需要指定读音的原文单独拆成片段，并填写 `reading`。送假名也可以拆成普通片段，例如“食べる”写成“食”带“た”，随后“べる”不带读音。

一个片段可以包含整个复合词；不必逐个汉字填写。中文的汉字留在 `zh`，不填写日语读音。`scene` 中的文字不参与自动注音。

### JSON 时间与显示规则

- 时间单位始终为毫秒，没有 59 分钟上限；1 小时为 `3600000`。
- `dialogue` 的 `endMs` 可以省略，此时取下一条开始时间更晚的台词开始处；最后一条延续到音频结束。推荐精确制作时填写结束时间。
- `scene` 必须填写结束时间，可与后续台词重叠，在独立提示区域显示；不会因为下一条台词开始而立即被抹去。
- 同一开始时间的不同条目按数组中的原始顺序保留；排序稳定，不按时间去重。
- 明确重叠的台词可以同时存在；画面需保留所有当前有效内容。
- `endMs` 超过音频时长时，实际显示在音频结束处停止，文件本身保持原样。
- “中 / 日 / 双”只过滤语言字段；时间、当前有效条目和播放器进度共用，不加载另一份单语文件。

### 修订、读音优先级与校验

用户个人修正 > 字幕明确提供的 `reading` > 离线自动读音。切换语言不会改变这一优先级。

这三层可以同时使用。字幕已完整提供读音时，直接显示文件中的假名；只提供部分词时，缺少读音的日文部分再进行离线分析。假名开关只控制显示，不删除文件读音或个人修正。

应用用音轨、`documentId`、条目 `id`、原文及内容指纹核对个人修正。若原文发生变化，旧位置修正不会直接套用；相同 ID 不能作为忽略原文变化的理由。自动缓存还需记录算法/词典版本。

不支持的 `version`、重复 ID、无效时间、无语言内容和无效结构都应显示明确错误或对应条目警告；不能静默猜测出另一种含义。字幕读取失败时播放器继续可用。

可供编辑器使用的 JSON Schema 见 [himitsu-subtitles-v1.schema.json](himitsu-subtitles-v1.schema.json)。Schema 检查字段与类型；ID 唯一性、结束时间先后等跨字段语义还要由应用检查。
